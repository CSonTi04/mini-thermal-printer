# PC BLE discovery and read-only queries: 2026-07-25

## Result

Windows connected directly to the printer's BLE interface. Live GATT
enumeration verified the statically recovered `FF00` service layout, and a new
credit-aware Python transport successfully ran the read-only CQRS query suite.
No print, feed, configuration, or other state-changing command was sent.

## Verified GATT layout

| Service | Characteristic | Properties | Role |
| --- | --- | --- | --- |
| `FF00` | `FF01` | notify | command responses |
| `FF00` | `FF02` | write, write without response | command transmission |
| `FF00` | `FF03` | notify | credits and packet-size control |

The printer's FF03 control message requested a 100-byte packet payload, while
Windows exposed a 20-byte maximum for write-without-response. The adapter uses
the safe minimum, so its effective packet size is 20 bytes. Credit
notifications permitted all five short query writes; four credits were
available when the query session completed.

Additional vendor services were present but are not used by this driver:
`18F0`, `E7810A71-73AE-499D-8C15-FAA9AEF0C3F2`, and
`49535343-FE7D-4AE5-8FA9-9FAFD205E455`.
